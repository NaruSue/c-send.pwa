# c-send デスクトップラッパー要件

## 状態

Tauri 2ラッパー v0.0.2を[GitHub Releases](https://github.com/NaruSue/c-send.pwa/releases/tag/wrap-v0.0.2)で公開しました。PWA連携API v1はPWA 0.2.1に対応します。Windows x64、macOS Apple Silicon、Ubuntu 22.04 x64向けの配布物を掲載しています。v0.0.1で起動できない場合はv0.0.2を上書きインストールしてください。詳細は[連携API仕様](api-contract.md)を参照してください。

## 目的と構成

- `wrap/` は既存のc-send PWAをデスクトップウィンドウで利用する薄いラッパーとする。
- アプリは正式公開中のPWAを読み込む。PWAの画面・テンプレート機能はWeb側で更新できるようにし、ラッパー本体の更新とは分ける。
- ラッパーのソース、PWAからラッパーを制御するAPI、そのAPIを使うPWA側コードは、同じ `c-send.pwa` リポジトリで管理する。
- デスクトップアプリはTauri 2を使う。
- 対象OSはWindows、macOS、Linux。初回LinuxビルドはUbuntu 22.04 LTS x64。配布形式はAppImageとdeb。Ubuntu 24.04を含む他の環境での動作確認は今後行う。
- macOS初版の配布対象はApple Silicon（arm64）。Intel Macは対象外。
- モバイルOSのキーボード機能はこのデスクトップラッパーの対象外とし、既存の `wrap/key/` 構想で別に扱う。

## ウィンドウ

- タスクトレイから開くクイック選択リストはラッパーが表示する。PWAは現在の表示状態に合うリストを送信する。
- 絞り込みがない場合、クイック選択画面には並べ替え順の先頭20件を表示する。
- 検索語を入力した場合は表示対象全体を検索してから、現在の並べ替え順で結果の先頭20件を表示する。
- クイック選択画面はPWA画面ではなく、ラッパーが受け取ったリストを使って表示する。検索欄などを置けるよう、OSのネイティブトレイメニューだけに依存しない。
- 通常画面でのコピーは従来どおりPWAが行う。タスクトレイのクイック選択から選んだ場合だけラッパーがコピーする。
- クイック選択で通常テキストを選ぶと、ラッパーが受け取った本文をクリップボードへ書き込む。テンプレート形式はPWAの展開コールバックで展開し、結果をラッパーへ返してからラッパーがコピーする。
- コピー成功後、ラッパーは選択項目IDをPWAへ通知する。PWAは利用回数と最終利用日時を更新し、更新後のリストをラッパーへ再送する。コピー失敗時は利用履歴を更新しない。
- 項目を選んでコピーしたら、クイック選択リストを閉じる。右クリックの制御メニュー内でサブメニューを開く操作では、親メニューを閉じない。
- 通常画面・クイック選択画面のウィンドウサイズと位置を端末内へ保存し、次回表示時に復元する。保存位置が現在の画面範囲外なら、操作できる位置へ戻す。両画面を同じネイティブウィンドウの表示モードとして実装する場合は、同じウィンドウ状態を使う。
- 常に手前に表示する設定を全対象OSで提供し、現在の状態を切り替えられるようにする。
- トレイが使えない環境では、アプリ画面の表示・非表示切替を使えるようにする。

## トレイ操作

トレイは、OSおよびデスクトップ環境が対応する場合だけ提供する。macOSのメニューバーアイコンも同じ操作体系に含める。Tauri 2のイベントを利用し、利用可能な環境で次の動作を提供する。

- 左クリック：ラッパーのクイック選択画面を表示する。
- ダブルクリック：通常画面を表示する。
- 右クリック：制御メニューを表示する。
- 項目を選んでコピーしたら、クイック選択リストを閉じる。
- サブメニューの操作中は親メニューを維持する。

Tauri 2のLinuxトレイアイコンは表示できてもクリックイベントは配信されず、右クリックでコンテキストメニューを開く動作になります。Linuxではトレイメニューからクイック選択・通常画面・表示切替を行います。トレイが使えない環境では `Ctrl+Shift+Space` で通常画面の表示・非表示を切り替えます。左クリックでリスト、ダブルクリックで通常画面という操作はWindows/macOS向けです。Ubuntu 22.04と24.04のX11/Waylandでトレイ表示、WebKitGTK、最前面表示を確認します。AppImageもWebKitGTKなどOS側ライブラリに依存するため、すべてのLinuxディストリビューションとの互換性は保証しません。debはaptで依存関係を解決します。

## PWA・ラッパー間API

APIは同一リポジトリ内で契約を定義し、PWAとラッパーを別々に更新できるようバージョン管理する。ブラウザー版ではAPIが存在しなくても通常のPWA機能を維持する。

| API／イベント | 方向 | 用途 |
|---|---|---|
| `getInfo()` | PWA → ラッパー | ラッパーバージョン、連携APIバージョン、OS、利用可能な機能を返す |
| `publishQuickList(snapshot)` | PWA → ラッパー | クイック選択リストを送る。項目の追加・削除、利用履歴、絞り込み、並べ替えの変更時と画面表示時に更新する |
| `onTemplateResolve(callback)` | ラッパー → PWA | テンプレート項目の選択時に項目IDを渡し、PWAが展開した結果を受け取る |
| `onItemUsed(callback)` | ラッパー → PWA | ラッパーでコピーに成功した項目IDを受け取り、PWAが利用回数と最終利用日時を更新する |
| `setAlwaysOnTop(enabled)` | PWA → ラッパー | 最前面表示を切り替える |
| `onLog(callback)` | ラッパー → PWA | ラッパーの診断用ログ情報をPWA側へ通知する。ログは端末内で扱い、自動送信しない |

`publishQuickList`のスナップショットはPWAの現在の表示対象と並び順に一致させ、最大20件とする。ラッパーがテキストをコピーできるよう、項目ID、タイトル、本文、形式、タグなど必要な項目データを含める。認証情報は含めない。ロック中の保護項目は送らず、保護状態が変わったときはラッパー側の古いリストも更新または消去する。

コピー結果はラッパーからPWAへ項目IDで通知し、PWA側の利用履歴を正とする。通常画面のコピー処理は変更しない。ラッパーのログにはテンプレート本文、クリップボード内容、認証情報を含めない。ログの保管範囲・保持期間は実装時に定める。ネイティブAPIの利用権限は正式PWAの信頼済みURLに限定し、許可するコマンドを必要最小限にする。

詳細なAPI契約は[ラッパー連携API仕様](api-contract.md)に記載する。

## 終了と起動

- トレイ対応環境で通常画面の閉じるボタンを押した場合は、終了せずトレイへ格納する。
- トレイ非対応環境で閉じる操作をした場合、および制御メニューから終了を選んだ場合は、終了確認を表示する。
- PC起動時の自動起動は未決定。初期値をオフにする案を候補とする。

## 保存データ

- ウィンドウ位置・サイズ、最前面表示などラッパー固有の設定は端末内だけに保存し、アカウントやクラウドへ同期しない。
- ラッパー内PWAのWebView保存領域は通常ブラウザーと別になる。ブラウザー内だけに保存されたローカル項目は、自動ではラッパーへ移らない。
- テンプレートの保存・同期は既存PWAの仕様と、利用者が選んだ同期設定に従う。
- ラッパーの更新でWebViewの保存領域を変更しない。アンインストール後もローカルデータが残るかはOS・配布形式に依存するため、保持を保証しない。

## 更新とリリース

- PWA本体は公開URLから読み込み、GitHub Pagesから更新する。画面機能の更新だけならラッパーの再配布を必要としない。
- ラッパー本体はPWAとは別のバージョンを付け、セキュリティ対応またはネイティブ機能の変更時を中心に更新する。
- PWAとラッパーのバージョン番号は独立させるが、各ラッパーリリースには動作確認済みのPWAバージョン／連携APIバージョンを記録する。PWA側にも、必要な最小ラッパーAPIバージョンと互換性を記録する。
- ラッパーは公開URLから最新PWAを読み込むため、リリースごとにPWAの固定コピーは内包しない。PWAを先行更新しても既存ラッパーが動くよう、連携APIは互換性を保ち、新APIは機能検出で利用する。
- 初回ラッパー版は `0.0.1` とし、PWA本体のバージョンとは独立して管理する。
- PWAと同じリポジトリのGitHub Releasesを使うため、ラッパーのGitタグは `wrap-v0.0.1` のように `wrap-` を付ける。Tauriアプリのバージョン値は `0.0.1` とし、タグの接頭辞を含めない。
- GitHub ActionsでWindows・macOS・Linuxのリリースビルドを行い、各OSの配布物を同一のGitHub Releaseへ添付する。リリースタグのpushを起動条件とする。GitHub PagesへのPWAデプロイワークフローとは別にする。
- ビルド生成物はソース管理へ含めない。Updater用署名ファイルとリリース情報もActionsから公開する。
- Tauri Updaterを使い、利用者がアンインストールして手動で入れ直さずに更新できるようにする。更新は署名検証し、自動適用せず確認を経て行う方針とする。
- Windowsの更新ではアプリが終了する。macOS・Linuxでは更新後にアプリを再起動する。
- LinuxはUbuntu LTSを基準にAppImageを第一候補とし、対象バージョンと追加パッケージの要否をビルド・動作確認後に確定する。
- macOSは当面、ダウンロード時の未公証警告を許容する。警告を避けたい利用者はPWA版を利用できるよう案内する。
- macOSの配布署名と公証は初回リリースの必須条件にしない。Tauri Updaterの更新署名鍵は別途必要とし、秘密鍵をGitへ登録しない。

## PWA連携APIとセキュリティ

- PWA側のTauri連携ブリッジとAPI契約は実装済み。通常ブラウザーではTauri APIを検出せず、既存のPWA機能をそのまま使う。
- Tauri側は`withGlobalTauri`または同等の公開ブリッジでTauri 2の`core.invoke`と`event.listen`を利用できるようにし、API仕様にあるコマンド・イベントを実装する。
- ネイティブ機能を呼ぶPWA連携APIは、ブラウザー版では利用できない場合も通常のPWA機能が動くよう、機能検出して使う。通常画面のコピーはPWAが行い、ラッパーのクリップボード操作はクイック選択での項目選択に限定する。
- ネイティブAPIは表示・非表示、最前面切替、必要なウィンドウ操作などに限定する。
- リモートPWAからネイティブAPIを呼べる範囲は正式PWAの信頼済みURLに限定し、Tauri capabilityも必要最小限にする。任意サイトの遷移先へネイティブ権限を渡さない。
- PWAとラッパーを別々にリリースできるよう、PWA側の連携APIはバージョン互換性を保ち、未対応APIがある古いラッパーでも通常のPWA利用を妨げない。
- 対応表はPWAの版、ラッパーの版、連携APIの版、確認したOSを記録し、PWAとラッパー双方のリリースノートから参照できるようにする。
