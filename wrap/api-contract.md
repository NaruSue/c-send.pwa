# デスクトップラッパー連携API仕様

## 状態

APIバージョンは`1`。PWA側は0.2.3。Tauri側は`wrap-v0.0.5`。

## 担当範囲

- 通常画面では、PWAが従来どおり項目を展開してクリップボードへコピーする。
- タスクトレイのクイック選択では、ラッパーが受信済みの項目名をOS標準メニューに直接表示する。別ウィンドウは作らない。
- PWAは表示状態に合うリストデータをラッパーへ送り、以後の一覧描画を担当しない。
- クイック選択で通常テキストを選んだときは、ラッパーが本文をクリップボードへ書き込む。
- クイック選択でテンプレートを選んだときは、ラッパーがPWAの展開コールバックを呼ぶ。PWAは既存の展開処理を使い、結果を返す。クリップボードへの書き込みはラッパーが行う。
- コピー成功後、ラッパーは項目IDをPWAへ通知する。PWAは利用回数と最終利用日時を更新して保存し、更新後のリストを再送する。
- ラッパーでのクリップボード操作はクイック選択に限る。通常画面でのコピー動作は変えない。

## API

| API | 呼び出し方向 | 契約 |
|---|---|---|
| `getInfo()` | PWA → ラッパー | `wrapperVersion`、`apiVersion`、`os`、`capabilities`を返す。PWAは機能の有無を判定し、通常のWeb動作を維持する |
| `publishQuickList(snapshot)` | PWA → ラッパー | 現在のPWA一覧から生成したクイック選択リストを送る。最大20項目 |
| `onTemplateResolve(callback)` / `respondTemplate(...)` | ラッパー → PWA → ラッパー | テンプレート選択イベントをPWAへ送り、PWAが展開結果を応答する |
| `onItemUsed(callback)` | ラッパー → PWA | コピー成功後の`itemId`と利用日時を通知する。PWAが利用履歴を更新する |
| `setAlwaysOnTop(enabled)` | PWA → ラッパー | 最前面表示を切り替える |
| `onLog(callback)` | ラッパー → PWA | ラッパー診断ログをPWA側へ通知する。ログを自動でサーバー送信しない |

## リスト送信

PWAは通常一覧と同じ項目データ、検索・タグ・保存先フィルター、並べ替えの結果を使う。フィルター未指定時は現在の並べ替え順の先頭20件、検索時は全表示対象を検索した結果の先頭20件を送る。

```json
{
  "apiVersion": 1,
  "items": [
    {
      "id": "stable-pwa-item-id",
      "title": "表示タイトル",
      "value": "コピー本文またはテンプレート本文",
      "mode": "plain",
      "tags": ["例"],
      "source": "local"
    }
  ]
}
```

`mode`は`plain`または`template`。クイック選択で通常テキストを選ぶ場合、ラッパーは`value`をそのままコピーする。テンプレートの場合は`itemId`でPWAの最新項目を特定して展開を依頼する。本文はラッパーとのローカル連携にのみ渡し、ラッパーの診断ログや外部通信には含めない。

保護タグ付き項目はロック中に送らない。保護状態が変わった場合、PWAは新しいリストを送り、ラッパーは古い項目データを置き換えるか消去する。メニューを開いている間にリストが更新された場合は古いメニューの項目選択を拒否する。項目の追加・削除、本文変更、利用履歴、絞り込み、並べ替えの変更時にリストを同期する。

## テンプレート展開とコピー

テンプレート選択時、ラッパーは`c-send-template-resolve`イベントで項目IDと一意な`requestId`を送る。PWAは`onTemplateResolve(callback)`で受け取り、自身の項目データを使って現在のテンプレート展開ロジックで処理する。PWAは`respondTemplate(requestId, itemId, result)`を呼び、要求に対応する応答を返す。成功応答は`payload.text`、失敗応答は汎用エラーとする。

```json
{
  "requestId": "request-id",
  "itemId": "stable-pwa-item-id",
  "context": {
    "clipboardText": "必要な場合に限り、選択時点のクリップボード文字列"
  }
}
```

```json
{
  "requestId": "request-id",
  "itemId": "stable-pwa-item-id",
  "payload": {
    "text": "展開済みテキスト"
  }
}
```

`{{clipboard}}`、`{{sort}}`、`{{unique}}`、`{{calc}}`、`{{json}}`、`{{uri_encode}}`、`{{uri_decode}}`など、現在のクリップボード文字列を参照するテンプレートでは、非表示WebViewのクリップボード権限に依存しないよう、ラッパーが選択時点の文字列をローカルコールバックで渡す。該当するテンプレートで必要な場合に限り渡す。通常テキストには渡さない。

ラッパーは`payload`をクリップボードへ書き込む。将来の形式拡張に備え、`payload`はオブジェクトとし、初版では`text`のみを定義する。コピー完了後、ラッパーは`c-send-item-used`イベントで`itemId`と`usedAt`を送る。PWAは`onItemUsed(callback)`で受け取る。展開またはコピーに失敗した場合、ラッパーは利用通知を送らず、利用履歴を更新しない。

## 利用履歴通知

```json
{
  "itemId": "stable-pwa-item-id",
  "usedAt": "2026-11-27T12:34:56.000Z"
}
```

PWAは対象項目の`usageCount`を1増やし、`lastUsedAt`を`usedAt`に更新する。保存後に再描画し、通常一覧の並べ替えとラッパーへ送るクイック選択リストを更新する。ラッパーは利用回数を独自保存せず、PWAの履歴を正とする。

## バージョン・ログ・セキュリティ

- APIがないブラウザーではネイティブ連携を無効にし、PWA単体の利用を続ける。
- 新しいAPI機能は`capabilities`で検出し、古いラッパーに未対応機能があってもPWAの通常利用を妨げない。
- ネイティブAPIの権限は正式PWAの信頼済みオリジンに限定し、許可する操作を最小限にする。
- `onLog`にはテンプレート本文、クリップボード文字列、認証情報を含めない。ログは自動アップロードしない。
- リスト本文とテンプレート展開結果はローカルのPWA・ラッパー連携内でのみ扱う。診断ログや外部サーバーへ含めない。
- APIバージョン、ラッパーバージョン、対応OSの組み合わせをリリースごとに記録する。
